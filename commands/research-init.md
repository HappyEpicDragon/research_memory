---
description: 全量扫描当前仓库，建立初始的 .research/ 记忆（state.md / compute_nodes.md / 日志文件）
---

给一个还没有 `.research/` 目录的项目建立初始记忆。**只在 `.research/state.md` 不存在时才这样从零开始**；如果已经存在，先用 `AskUserQuestion` 确认用户是不是真的要重新初始化（会覆盖），不要默默覆盖已经在用的记忆。

## 第一步：扫描仓库，收集"代码能告诉你的东西"

不要问用户这些，自己去看：

1. `git log --oneline -20` 和 `git log --reverse --oneline -1`：最近在做什么、项目起于什么时候。
2. 仓库根目录的 README / 任何顶层的 `.md` 说明文档。
3. 目录结构总览（排除 `.git`、`node_modules`、`__pycache__`、数据/权重这类大体积目录）：项目大致是什么类型、代码怎么组织的。
4. 有没有已经存在的实验代码/配置（`conf/`、`outputs/`、`experiments/`、任何看起来像训练脚本或 notebook 的东西）、已有的结果文件。
5. 有没有看起来像论文草稿的东西（`.tex`、`paper/`、`draft/`）。

这一步只做事实收集，**不要替用户下结论"项目现在处于什么阶段"**——代码看得出"有什么"，看不出"为什么"和"接下来打算干什么"，这两块必须问用户，不能编。

## 第二步：问用户几个问题，把代码看不出来的部分补上

用 `AskUserQuestion`（或者如果问题不适合选项形式，就直接用文字问），确认：

- 这个项目研究的是什么问题 / 核心方法是什么（一两句话）
- 现在大致到了哪个阶段（比如：刚开始 / 方法基本定了在跑实验 / 实验做得差不多在写作 / 卡住了在等某个决定）
- 有没有已经确定不再改的决策，或者已经放弃的方向（这些之后会进 `decisions.log.md`）
- 有没有已知的坑/红线，写代码或做判断时必须遵守的

不要一次性问太多细节，问到能写出一份诚实、不臆造的 `state.md` 就够。

## 第三步：落盘

1. 用 `templates/state.md.tmpl` 的结构写 `.research/state.md`：术语表（如果第一步扫描发现项目里已经有一些专有名词/缩写，先收进来解释）、现在是什么状态、为什么是这个状态、接下来打算做什么、已知的坑。遵守 `SKILL.md` 核心规则一——200 行上限，面向不了解背景的人。
2. 用 `templates/compute_nodes.md.tmpl` 创建空的 `.research/compute_nodes.md`。
3. 创建空的 `.research/decisions.log.md` 和 `.research/experiments.log.md`（各自带上标准的"追加型日志"说明头，不需要写任何历史条目）。
4. 创建空的 `.research/archive/` 目录。
5. 完成后用几句话告诉用户 `state.md` 里写了什么，让用户检查扫描 + 问答得出的结论是不是准的——**这是模型第一次替这个项目总结现状，出错的概率比后续增量更新时更高，值得用户花一分钟看一眼**。
